# SmartVPN Rust core: phase 1

Status: implemented and parity-tested, NOT activated in the running application.
Flutter, Mihomo, the Go service, existing HTTP APIs, profiles and network settings are unchanged.

## Scope

A dependency-free Rust library ports these pure parts of backend/stun.go and backend/speedtest.go:
- STUN binding request encoding (caller supplies a fresh cryptographically random 12-byte transaction ID).
- STUN mapped/XOR-mapped IPv4 and IPv6 address decoding, including Go-compatible IPv4-mapped IPv6 formatting, padding, plain-address fallback, errors, and clipped message lengths.
- Throughput conversion from signed byte counts and signed elapsed nanoseconds to Mbps.

There are no sockets, process launches, registry operations, database operations, node connections, or system-network changes in the library. The parser deliberately preserves existing Go behavior rather than silently tightening validation. The future network caller must still validate the transaction ID; this parser alone is not a complete STUN security check.

## Validation

Run in this directory:

    cargo test --offline --locked
    cargo fmt --check
    cargo clippy --offline --locked --all-targets -- -D warnings

The six Rust integration tests cover:
1. Seven throughput cases including negative/zero inputs.
2. Exact request bytes and caller-supplied transaction ID.
3. 197 deterministic response fixtures generated by the ORIGINAL Go parser (valid IPv4/IPv6/mapped IPv6, port edges, truncated data, bad headers, unknown attributes, attribute padding, fallback and mutations).
4. 512 arbitrary inputs plus 492 forced-header variants, checked for panics.
5. C ABI output/error/buffer/null-pointer contracts.
6. Exact Go duration-to-seconds rounding at a large nanosecond value.

Regenerate oracle fixtures after an intentional Go behavior change:

    python verify_go_parity.py <repository-root> <absolute-path-to-go.exe>
    cargo test --offline --locked

The script copies only pure Go functions to a temporary program, uses no downloads, and never starts the Go service or a VPN. It replaces the fixture files in this crate only. Review fixture changes before accepting a behavior change. Source SHA256 is recorded in tests/fixture-source.txt.

Verified with Rust 1.95.0 on Windows x64, including a real DLL loaded by the Go bridge. Android compilation and Android FFI are not yet verified.

## Integration and rollback plan

This is the first extracted module, not a replacement HTTP service and not a production cutover. Existing Go call sites remain authoritative. There is no startup-script change and no automatic runtime selection.

The optional Windows x64 bridge below defines the first narrow ABI. Production builds remain Go by default. Preserve current Flutter HTTP shapes, status codes, errors and settings/database formats. Do not cut over connection ownership, TUN, DNS, routes or Mihomo lifecycle until platform integration tests and rollback behavior are verified with user authorization for any networking effects.

Suggested subsequent extraction: node/subscription parsing, routing configuration generation, then persistence with migration/rollback tests. Network lifecycle work comes last.

Rollback now: do not build/use this independent crate; the existing Go application is already unchanged. No personal configuration restoration is needed.

## Phase 1B: opt-in Windows x64 bridge

The Go call sites now have a build-time adapter. Default builds still use Go.
A Windows x64 build with `-tags rustcore` can load this crate's DLL using
`SMARTVPN_RUST_CORE_DLL=<absolute path>`. Empty/relative/missing DLL paths or
missing ABI symbols fall back to Go. The selection is fixed at first call for
the lifetime of that process; changing it requires a restart. Do NOT restart a
live service just to test the migration.

Build the Rust DLL with `cargo build --release --offline --locked`. Keep that
artifact in a test directory; no runtime package is replaced by these steps.
The Go bridge loads only an explicitly specified absolute path with restricted
DLL dependency search. Only point it at the locally built, trusted DLL. Native
code is loaded into the process; arbitrary DLLs must not be used.

The versioned C ABI has two integer/pointer-only entry points:
`smartvpn_parse_stun_v1` (UTF-8 result/error in caller-owned memory), and
`smartvpn_throughput_v1` (f64 output through a caller-owned pointer). It requires
no CGO. Windows ARM64 and Android remain on Go. No random-number source, HTTP,
Mihomo lifecycle, user configuration or network state has migrated yet.

To exercise ONLY the safe bridge test from the Go backend directory, set:

    SMARTVPN_RUST_CORE_DLL=<absolute locally built DLL>
    SMARTVPN_TEST_EXPECT_RUST=1
    SMARTVPN_TEST_RUST_FIXTURES=<absolute path to tests/stun-fixtures.tsv>

then run:

    go test -tags rustcore -count=1 -run '^TestRustCoreBridgeParity$' .

For the missing-DLL fallback test, use an absent absolute DLL path and set
`SMARTVPN_TEST_EXPECT_RUST=0`; rerun the same command in a fresh process.
These are process-local environment variables, not system settings. Do not
set them globally. The original application's build/package scripts were not
changed. A normal build without `rustcore` is the rollback path.

Production cutover, live VPN testing and Android ABI integration remain future phases.

## Phase 2: subscription/node input parsing (2026-11-16)

The optional Windows Rust path now handles six more pure functions:
`decodeSubscriptionBase64`, `isProxyURILink`, `hasProxyURI`,
`isInformationalNode`, `isInlineSubscription`, `categorizeSubscriptionInput`.
They are called by the existing Go subscription importer and node/profile parsers.
Base64 handles standard/URL-safe and padded/raw encodings, Go Unicode whitespace
and permissive unused tail bits. Classification preserves original order,
case rules, announcement filtering and existing behavior rather than silently
changing accepted inputs. This is the input layer, NOT a complete port of the
protocol-specific node object converters or YAML/Sing-Box parsing.

A new optional `smartvpn_subscription_v1` export avoids breaking phase-1 DLLs:
old DLLs still provide STUN/throughput, while subscription calls fall back to Go.
Invalid UTF-8 or bridge failures also fall back. Inputs over 8 MiB and requested
outputs over 16 MiB use Go instead, without imposing a new rejection on the API.
No logging or persistence is performed on subscription data by this module.

Additional safe test:

    SMARTVPN_TEST_EXPECT_SUBSCRIPTION_RUST=1
    go test -tags rustcore -count=1 -run '^TestRustSubscriptionParity$' -v .

Use the DLL path described above. Set expected-subscription-Rust to 0 to test an
old phase-1 DLL or an absent DLL. The test compares 10,219 synthetic inputs across
all six functions; for valid UTF-8 it also asserts the new bridge was actually
used, so fallback cannot hide parser differences. No real links/credentials are
read. Both disabled/default Go and DLL fallback remain covered. See VALIDATION.md.

Still pending: full VMess/VLESS/Shadowsocks/etc. canonical proxy conversion,
Clash YAML/Sing-Box JSON parsing, persistence/config generation, HTTP service,
Android native integration and runtime network acceptance. Existing Go continues
to implement those. Do not enable the experimental build on a live VPN just to
validate this source migration.

## Phase 3: VLESS / Trojan / Hysteria2 field conversion

Rust now constructs canonical proxy fields for three URL-shaped protocols:
VLESS (TLS and Reality, public key/short ID, fingerprint, flow), Trojan
(password, SNI/peer, ALPN and TLS verification flags), and Hysteria2
(password, SNI, ALPN and obfuscation options). VLESS/Trojan transport options
cover TCP, WebSocket, gRPC and HTTP/2 with original field omission behavior.

Boundary is intentionally narrow: Go still parses URLs and query escaping,
validates host/port, resolves the display name, and constructs the final
manualNode wrapper. Rust receives these normalized fields over a length-prefixed
binary ABI and returns a typed proxy map. It does not parse an arbitrary URL,
change any client settings, connect to the node or persist credentials. Go
map types (including integer port and []string ALPN) are preserved exactly.

Only `rustcore` Windows x64 builds opt in. Old DLLs without
`smartvpn_node_fields_v1` use Go for these converters while retaining any earlier
Rust capabilities. Invalid UTF-8, malformed wire or bridge-size limits fall back.
Semantic validation errors remain errors, not a silent success. Unsupported
transport quoting is formatted by Go to retain exact existing error text.

Safe test (with phase-3 DLL path and prior test environment variables):

    SMARTVPN_TEST_EXPECT_NODE_RUST=1
    go test -tags rustcore -count=1 -run '^(TestRustNodeFieldsParity|TestRustNodeWireRejectsMalformed)$' -v .

Use expected-node-Rust=0 for an older or missing DLL. 3,593 synthetic field cases
compare full typed nodes and exact error strings against original Go. They cover
Reality, defaults, IPv6, invalid endpoints, credentials, Unicode/whitespace,
query flags, transports, ALPN, field omission and a large synthetic path.
No real subscriptions or secrets are read. No third-party Rust dependency was
added; all builds remain offline.

Still Go: VMess, Shadowsocks/SSR, TUIC, Hysteria v1, URL grammar, complete YAML/JSON
profile conversion, persistence, HTTP service and network lifecycle. No production
cutover or Android ABI/device validation is claimed.

## Phase 4: TUIC and Hysteria v1 field conversion

The optional Rust path now constructs TUIC UUID/password, congestion-control,
SNI, ALPN, insecure flags and UDP relay mode, plus Hysteria v1 authentication,
up/down bandwidth, SNI, ALPN and obfuscation fields. Alias precedence, whitespace,
missing-user behavior, and Hysteria's original 1..65535 integer bandwidth rule
are preserved. This is field conversion after Go URL/endpoint/name processing,
not a reimplementation of the network protocols or full URL grammar.

`smartvpn_node_fields_v2` advertises these two new kinds. The Go adapter requires
v2 for TUIC/Hysteria; a phase-3 DLL continues to serve the earlier three kinds
and falls back to Go for the new two. The v1 wire format and codes are unchanged.
TUIC's separate username/password are adapter-owned internal fields populated
from URL userinfo, never from similarly named remote query parameters.

With phase-4 DLL selected:

    SMARTVPN_TEST_EXPECT_EXTENDED_NODE_RUST=1
    go test -tags rustcore -count=1 -run '^(TestRustExtendedNodeParity|TestRustExtendedInvalidUTF8Fallback)$' -v .

5,560 synthetic cases compare full typed nodes and exact error strings to Go,
including nil/empty userinfo, whitespace usernames, password-only forms, query
aliases, malformed bandwidth, IPv6 and a query-key spoofing regression. Invalid
decoded UTF-8 is explicitly verified to use the Go fallback.

Current migrated protocol FIELD constructors: VLESS, Trojan, Hysteria2, TUIC,
Hysteria v1. Still Go: VMess, Shadowsocks/SSR constructors, URL/JSON/YAML grammar,
full profile conversion, persistence, HTTP service and network lifecycle.
Default build stays Go; no active VPN executable is replaced by this work.

## Phase 5: remaining node fields and service policy

Added VMess, Shadowsocks and ShadowsocksR canonical proxy-field construction via
`smartvpn_node_fields_v3`. Go retains link/JSON/Base64 grammar, endpoint/name handling,
normalization and compatibility fallback. This now covers fields for all eight
currently supported link schemes, not an entirely Rust URL parser.

Added Rust byte-log redaction, line-aligned tail trimming and pure service-takeover
decision. Existing Go I/O, process control and locking remain. Redaction uses linear
KMP scanning, including adversarial repeated-prefix coverage.

`CONTRACTS.md` and four offline Go tests freeze initial HTTP/auth/JSON/DTO boundaries;
they do not implement a Rust HTTP service. `MIGRATION.md` lists the remaining work.

Run the safe allowlisted validation from a child PowerShell Core process:

    pwsh -NoProfile -File backend-rust/test-offline.ps1 -GoExe <absolute-go.exe> -GoPath <cached-gopath>

The script requires installed Cargo/Go, cached Go dependencies and Windows amd64.
It checks Rust fmt/test/clippy/build, default Go, real DLL and missing-DLL fallback.
It does not run the unrestricted backend suite, the service, or actual connections.
Environment variables are confined to the child process. No execution-policy change
is needed; Windows PowerShell 5 may reject scripts where PowerShell Core is available.

## Phase 6: HTTP policy, traffic, configuration and storage candidate

Active opt-in Rust paths now include exact Bearer authorization, identity JSON,
reachable-node selection, traffic counter/rate/ranking, and configuration assembly
(including DNS/domestic rule assembly). Go still supplies exact string quoting,
platform TUN/entry-DNS snippets and rule classification for configuration generation.
The reference Go implementations remain separate and are used for differential tests.

Rust canonical route planning is an offline candidate only; Go still dispatches
business handlers. `../backend-rust-store` implements compatible SQLite persistence
as a separately tested candidate library, not a selected production database backend.
Read its README before using it. No production storage or listener was switched.

## Phase 7

Optional Rust execution now includes game-bypass normalization/rule assembly,
SOCKS port validation, health parameter clamping and pure health-state transitions.
Go retains platform path parsing, timestamps, real network probes, region pinning,
fail-closed decisions and scheduling. Existing health safety regressions remain green.

The SQLite candidate now includes traffic checkpoint/history transactions and report
queries with cross-language parity. Production Go SQL is centralized behind store
methods to permit whole-instance backend selection later. No production database
selection or dual-writer mode has been enabled.

### Profile pipeline continuation (phase 12)

The additional Windows `rustcore` experiment `SMARTVPN_RUST_PROFILE_FLOW=1`
selects the cache/download/fetch/merge continuation described in
[PROFILE_SERVICE.md](PROFILE_SERVICE.md). The default remains Go. Real filesystem,
HTTP, YAML algorithms, persistence and Mihomo adapters remain Go; this is not a
standalone Rust backend or a production cutover. Quota refresh is not yet covered.
`test-profile-offline.ps1` extends the prior safe regression runners. Android
ARM64 libraries compile, but Android Rust integration and device/runtime tests
are not established by those builds. Earlier stage-specific notes above describe
their historical verification scope.

content. Default Go, the safety mirror and Go IO/platform adapters remain.
