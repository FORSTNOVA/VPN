# Phase30: health, region and verification-job authority

The existing persistent service handle adds typed health parameters, health records, region records, region verification job state, blocked/reason/sweep-note and last-switch time. Traffic and path state share the same epoch, revision, command and Ack protocol. Persistent ABI v3 requires capability mask 7; old DLLs select whole-instance Go authority before use. Default builds remain Go.

Production application copies of these fields are removed. Domain commands and narrow queries replace whole-table read/modify/write. Map key versus record name, nil versus empty maps, independent store load failures and memory surviving failed saves remain compatibility requirements. Settings clear intent is consumed once rather than allowing an old settings snapshot to restore observations. Late region-job completion retains the original shared-job semantics, without inventing generation cancellation.

Go retains actual clocks, mutexes, workers, HTTP/OS/Mihomo resources and storage adapters. Immutable clock tokens preserve monotonic comparisons; recovery checkpoints validate their ownership. Rust health and region workflow planners operate the authority through explicit effects. Missing or uncertain authority must fail closed, not appear as an empty health table. No automatic production authority takeover is introduced.

Full snapshots and checkpoints intentionally include all domains. Routine metadata and per-record operations are narrow; native state payload limits reserve envelope space. Query buffers may grow, but mutating calls are never replayed for capacity growth. Actual selection, pinned region/node, ordinary settings and node catalog remain subsequent authority work.

Verification is offline only, with synthetic resources and temporary fixtures. The acceptance record separately tracks complete aggregate tests, independent review, Android compile-only checks and guarded source delivery. No real node probe, VPN operation, route/DNS/proxy change or user database access is performed. This phase does not complete a standalone Rust backend.

Focused checks: 523 Rust tests (410 unit and 113 integration/ABI); 1,400 randomized three-domain authority steps; 10,000-record native table with 10,000 narrow updates/queries; 30 delivery-fault sequences and 39 checkpoint corruptions. Explicit tests reject shared clock tokens across health records and traffic/path domains. Independent review corrected background-worker error containment, HTTP pre-response failures and patrol channel publication ordering. Native workflow cases assert zero normal continuation recovery; separate forced-Go faults are not counted as native execution. Aggregate and source-delivery completion remain recorded separately.
