# Phase28: long-lived traffic state authority

This is the first persistent Rust-owned application state domain. With SMARTVPN_RUST_SERVICE_STATE=1 on Windows amd64 rustcore and a compatible trusted core DLL, a service instance selects Rust once. Otherwise it selects Go before use. Rust retains the current-traffic baseline, sampling-error text, epoch/revision and one bounded most-recent command/ack record across requests. The old app.lastTraffic and app.trafficHistoryError production fields have been removed. Other application domains are still Go-owned.

All six traffic workflows use the same authority, including a Go planner continuation after a workflow fault. This is not per-request shadow state and not dual writing. Go owns the actual app mutex, monotonic time.Time values, ticker/channel and network/store resources. Native state holds opaque clock tokens, with committed/pending token storage bounded. Rate reads and baseline commits remain separate effects, preserving the original failure boundaries. Rare platform float-conversion extremes explicitly use Go arithmetic against a validated Rust-owned snapshot; they do not transfer state ownership.

Commands bind ID, epoch, expected revision, operation and entire payload. Duplicate identical commands do not reapply; conflicting IDs are rejected. Explicit acknowledgement clears Pending, and the native state itself rejects new writes while pending. A lost or invalid Apply/Ack reply is resolved by command-status validation, never blindly repeating a state mutation. An unresolved command fails closed; it is not silently replaced by an old Go snapshot or an invented zero baseline. Database recordTraffic calls are still external effects and are not made idempotent by state command IDs.

A controlled internal checkpoint-to-Go transfer is implemented and tested. It validates the full checkpoint, recent command/ack consistency, revision and live state, preserves the monotonic clock ledger, atomically replaces the authority and closes the former backend once. It is not an automatic production failover policy, and no public route/settings action to force it is introduced. Unresolved status/export errors stay explicit failures. Operational recovery currently means a controlled normal exit and restart without the Rust-state opt-in, not killing a live VPN process in this task. No restart was performed. Ephemeral rates/error state is not advertised as process-restart persistence; historical traffic remains in the existing store.

Lifecycle initialization owns the new backend until successful construction transfers it; failed construction closes it. Cleanup revokes the history channel before closing the authority under lock. A closed tombstone prevents lazy recreation. Queued stale loops check identity before reading authority, and post-close calls receive errors without making kernel/store requests. Borrowed locks are not released by backend cleanup. Recovered state failures are exposed as errors rather than empty HTTP200.

Compatibility retains the original semantics: not-running current preserves baseline; GET failure clears baseline only; collect does not change current baseline; absent store/not-running preserves old sampling error, successful collection clears it, and history query uses its initial error snapshot. Kernel normal-stop final collection remains distinct from exit/traffic-stop.

Read-only Flutter source checks confirmed the existing traffic/history route fields and integer-rate expectations. No frontend change or UI/device execution was performed. Testing uses fake clocks/IO/tickers and HTTP recorders, not real sockets, service startup, user database or VPN/network changes. Android remains compile-only; Rust-state selection is not enabled on Android by compilation.

Focused verification: 469 Rust tests; 326 safe default Go tests selected by the aggregate; 2,000 shared-authority randomized steps, 21 strict multi-request traffic calls with zero continuation recovery, and two expected post-close HTTP500 cases. Native fault tests cover Apply/Ack/status corruption, checkpoint rejection/transfer, and 15,000 consecutive commits with a bounded time ledger. Default/disabled/missing-DLL selectors passed; rare arithmetic compatibility is separately asserted rather than counted as native arithmetic coverage. Full aggregate and delivery verification is recorded separately.
