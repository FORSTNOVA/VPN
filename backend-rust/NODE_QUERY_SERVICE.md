# Phase26: node query and delay workflows

SMARTVPN_RUST_NODE_QUERY_FLOW=1 independently opts Windows amd64 rustcore builds into six complete workflows: nodes, list, latency, node-latency, wait and delay. Default Go and effect-by-effect continuation fallback remain. This is a workflow migration, not a standalone service or production cutover.

Rust controls offline cache/manual merging, online provider ordering/filtering/deduplication/projection, source-label decisions, latency/error responses and wait/decode sequencing. Go retains original node graphs, JSON/YAML/URL parsing, file/HTTP resources, secrets, clocks and mutexes. Native code receives URL equality/merged-source facts, not subscription credentials or controller secrets.

Online list first reads the group and its direct selection; profile errors are ignored, manual details override profile details, subscription provider precedes manual provider and individual provider failures are ignored. First valid noninformational name wins. Network prefers detail metadata, while Type/Alive are provider fields; only the original detail fields are projected. A provider result is a nonnil slice even when empty. Offline listing preserves cached duplicates/order and captured manual enumeration, resets Selected and reports proxyEnabled=false, preserving nil/empty response distinctions. Source-label default and original error messages are retained.

latency checks running under lock, releases it, probes for eight seconds, then reads current active selection. node-latency keeps the original lock through its health-configured timeout and response. wait uses monotonic Go time facts, a strict Before check and fifty-millisecond sleeps after every unsuccessful attempt, including deadline overshoot. No UnixNano substitute or hidden deadline clamp is added.

Explicit concurrency repair: unlocked calls capture immutable metadata/controller snapshots under short locks. Borrowed-lock entries never relock or unlock their caller. Connection, kernel, refresh, health, region-job and diagnose bindings are audited separately; existing callers that hold locks use the Locked entries. This avoids introducing deadlocks while removing unlocked mutable-metadata reads.

Transport preserves encoded query, timeout+12 seconds, exact HTTP200, 256KiB decode limit and close-once body ownership. Resources are registered before subsequent decisions; cleanup clears references before calling Close. The fixed-purpose arena replaces per-iteration state instead of growing across wait polls. Responses already committed are not written twice; native interruptions recovered before a response receive an error rather than an empty success. This does not add recovery of arbitrary panics to default Go execution.

Tests use synthetic metadata, fake clocks/sleep/HTTP and temporary files only. Borrowed adapter regressions execute real method bindings and mutexes but intercept transport, with no socket or real node probe. Real network, VPN, system settings, user databases and Android device runtime remain untested and untouched. Source delivery and final results are recorded separately.

Final focused verification after all review fixes: 416 Rust tests, 297 explicit safe default Go tests and 2,004 strict actual-DLL comparisons with zero recovery per case. Fault checks include 46 ABI boundaries, 24 borrowed/owned post-effect panics, three response panics, two real Close-callback panics and two real facade response-once/error cases; capacity64/cancel1200 and 15,000 fake poll iterations validate resource bounds. Nine original error formats and the default source label match their originals. Successful default/disabled/missing selectors passed. Full aggregate and delivery verification is tracked separately.
