# Phase32: subscription catalog and quota resource authority

The persistent service authority owns the ordered subscription catalog and profile-from-cache flag, alongside traffic, path, health/region/job and ordinary control state. Active subscription URL and merge interval remain in control, without a second catalog copy. ABI v5 requires capability mask 31; default Go and whole-instance fallback for older DLLs remain.

Catalog entries reference quotas by process-local handle. With the Rust quota export, registry load, profile record-use and quota refresh transfer the signed counter values into Rust. Catalog reads, including internal profile and settings reads, return independent copies of those values. Metadata-only workflow intents preserve the existing handle. Live entries, delete rollback and pending commands retain references through the existing catalog protocol. Since Phase 88 the lower-level restore and patch helpers also register Rust values. Each native registration owns its own counters, even when two rows receive the same input pointer. Only the fallback for cores without the quota export maintains the Go pointer identity table. Restart persistence stores ordinary values.

Ordered duplicates, first-ID versus all-ID updates, precise URL quota guards, ABA and last-completion behavior are preserved. Add truncation and delete shallow-snapshot rollback remain distinct. Save failure does not uniformly undo memory or earlier side effects. Full catalog projection is reserved for actual list/save/load boundaries, while single-entry queries, quota updates and reference checks are narrow.

Phases 79–80 added per-app Rust cached-node storage for replacement, label updates and detached queries. Go retains backing slices for settings and profile write-through and reconciles borrowed edits on snapshot. Phases 81–83 added separate native storage for manual records and active/named chains. The Go settings map, borrowed hop slices, source URIs and nested Proxy resources retain their compatibility roles. Settings/profile workflows use explicit one-time resource and catalog intentions rather than restoring stale snapshots. No old identity assertion is removed to claim migration completion.

All verification uses synthetic resources and temporary fixtures. No real subscription download, node probe, VPN/network setting, user database or installed binary is touched. Aggregate, independent-review, Android compile-only and guarded source-delivery evidence are tracked separately. This remains an incremental backend migration, not a completed standalone Rust service.

Focused verification: 583 Rust tests (437 unit and 146 integration/ABI), 1,800 five-domain random steps, 10,020 resource replacements with bounded ledgers, 22 delivery-fault cases and 11 entry-field checkpoint corruptions. Additional native tests enforce save-before-header timing, mixed-intent ordering and checkpoint first-ID/URL/nil-shape guards. Independent review closed zero-reference growth, registration/retirement failures, unknown-as-empty errors, and cross-domain fault gates. Native registry resource mirroring preserves Info pointer identity without weakening ordinary deep-clone isolation. Aggregate/original retest and delivery status are recorded separately.

Phase 85 reads detached quota values for list, save and quota-refresh responses. Subscription configuration updates patch the selected catalog row by ID, preserving the quota handle, timestamps and unrelated fields. The encrypted URL persistence boundary and URL guard on in-flight refreshes are unchanged. Android lifecycle and TUN acceptance is recorded in MIGRATION.md.
